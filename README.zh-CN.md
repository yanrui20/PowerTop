## 终于能看到 MacBook 真实的功耗了

macOS 从来不会直接告诉你「现在系统正在消耗多少瓦」。PowerTop 解决了这个问题。

它把清晰、实时的功率信息放在菜单栏和弹窗里，让你随时知道电脑的用电情况。

## 主要功能

- **菜单栏电量显示** — 电量与功率以数值和小标签上下两行显示，可分别开关。电量与功率列在低电量模式显示黄色、高电量模式显示白色，其它参数保持系统正常颜色；实际充电时在电量数字后显示小闪电，隐藏电量时跟随功率数字。紧凑间距仅作用于 PowerTop。
- **电源模式切换** — 分别设置使用电池和连接电源时的自动、低电量、高电量模式；不支持高电量的设备会禁用该选项。
- **菜单栏功率显示（可选）** — 需要时可在菜单栏直接看到 `23W` 这样的实时数字。
- **功率流向图** — 一目了然地看到功率是来自充电器、电池，还是两者同时提供。
- **即时功率数据** — 系统功耗、充电器输出、电池充电或放电功率。
- **充电器负载情况** — 显示你的适配器功率以及当前使用率。
- **电池概览** — 快速查看电量、健康度、温度和循环次数。
- **预估剩余时间** — 在 Popover 和详细参数中估算可用时间；支持 macOS 充电上限（80/85/90/95%）及 AlDente 等第三方工具。
- **详细参数窗口** — 自动识别电芯拓扑（如 3S2P）、串联组电压、并联节电流、充电状态与生命周期统计。

数据实时更新，即使在插拔电源的瞬间也能保持准确可靠。

## 为什么用户喜欢用它

- 想知道 MacBook 实际消耗了多少功率
- 想了解自己的充电器在高负载时是否够用
- 想看到电池什么时候在帮忙供电
- 希望有一个简单漂亮的方式查看电池健康和充电行为

它是一个小巧的原生 Mac 应用，只做好一件事 —— 没有多余功能，没有订阅。

## 安装方式

### 下载安装（推荐）

从 [Releases](https://github.com/kDolphin/PowerTop/releases) 页面下载最新的 `PowerTop.zip`：

1. 解压文件
2. 把 `PowerTop.app` 拖到「应用程序」文件夹
3. 首次启动：右键点击应用 → **打开**（应用未签名）

### 从源码构建

```bash
git clone https://github.com/kDolphin/PowerTop.git
cd PowerTop
bash build.sh
open build/PowerTop.app
```

## 使用方法

1. 打开 PowerTop，图标会出现在菜单栏。
2. 点击图标即可看到功率流向图和当前各项数据。
3. 在弹窗底部开启「菜单栏显示功率」，即可让功率数值常驻菜单栏。
4. 在「电源模式」中分别设置使用电池和连接电源时的模式。在菜单底部的设置区展开「管理员权限授权」，点击「授权或修复权限」完成授权后，即可同时使用立即刷新和电源模式切换。启动项管理也复用同一个后台服务，应用仍会重新读取系统设置确认模式切换结果。
5. 「菜单栏显示电量」默认开启，可与功率显示独立开关。
6. 点击「详细参数」可查看完整的功率和电池信息。

电源模式设置保存在系统中，不是充电上限。高电量模式取决于机型与系统支持。应用按电池刷新间隔同步电源模式，以保持菜单栏颜色准确；后台读取不会禁用模式按钮，旧读数不会覆盖刚切换的模式；耗能应用列表只在面板打开时定期读取。默认每 2 秒读取功率；点击面板底部的间隔数值后，才能编辑 1–300 秒的刷新间隔。点击“应用”会在右侧显示“已应用”并退出编辑；取消或关闭面板会丢弃未应用的输入。也可点击右上角刷新按钮立即读取。插拔电源及唤醒时仍会额外刷新。

### 管理员权限授权

安装后的可选服务只接受本次授权的 PowerTop 应用签名和当前用户，提供固定操作：电源模式切换、完整电池数据采样、启动项状态查询，以及经校验的第三方系统启动服务启用、停用、加载及卸载。服务端会再次检查 plist 路径、所有者、权限、服务标识及重复项，拒绝修改 Apple 服务及自身；后台记录仅返回授权用户和共享项。采样请求不会改变充电、电源模式或系统轮询配置。它不接收任意命令，不保存密码，不修改 sudoers。服务文件位于 `/Library/PrivilegedHelperTools/com.kdolphin.PowerTop.EnergyHelper` 和 `/Library/LaunchDaemons/com.kdolphin.PowerTop.EnergyHelper.plist`，由 root 持有。点击「移除授权」可通过系统授权卸载。

当前是本地签名构建，更新或重新编译后签名会变化，需要再次点击「授权或修复权限」。授权前建议将应用放进「应用程序」。构建与测试不会安装此服务。

### 使用大量能耗的 App

读取 macOS 系统电池菜单使用的 `systemstats_get_top_coalitions` 数据源。已核对 macOS 26.6.2 控制中心的默认参数：120 秒窗口、最多 5 项、阈值 60000。列表不是实时 CPU 排名，也不是每个 App 的瓦数；后台子进程会尽量归并到负责它的 App。由于采样时机不同，列表可能与系统菜单短暂不同。

此只读接口未公开，未来系统版本可能变更。接口或返回格式不可用时会明确提示，不能将读取失败当作「没有使用大量能耗的 App」。列表只在面板打开时每 5 秒查询，手动刷新也会查询。点击列表或「打开活动监视器」可以查看系统详情。

功率来源统一按“有效系统功率读数 → 对应组件的电流 × 电压 → 其他独立功率做差估算”选择。电池优先 `BatteryPower`，其次为 `InstantAmperage × Voltage`、平均 `Amperage × Voltage`；充电器优先 `SystemPowerIn`，其次为 `SystemCurrentIn × SystemVoltageIn`。系统功耗优先读取有效的浮点瓦数 `BatteryData.SystemPower`，其次使用 `PowerTelemetryData.SystemLoad`，最后才做功率平衡估算。两项直接读数均保留相同的一致性检查。若电池读数表明正在充电，系统功耗却高于适配器输入，则拒绝该冲突读数；不能只回退电池功率，却继续保留不可能成立的系统功耗。整数形式的 `BatteryData.SystemPower` 单位不确定，不会直接使用。不会把充电器输入电压、电流算成系统自身功耗。有效零值会保留；两项数据缺失时不会互相循环推算，无法获得的值显示“—”。关系图的电池节点使用自身读数，不再复用系统节点。原始电池电流及 `BatteryPower` 的正数表示充电，负数表示放电，应用在读取时统一换算符号。充电时顶部和菜单栏瓦数是包含充电的适配器总输入。

定时刷新与「立即刷新」都通过管理员服务请求新采样，最多等待 10 秒，确认 UpdateTime 推进后再读取数据。手动刷新会等待正在进行的采样；定时任务遇到采样进行中则跳过，不堆积请求。休眠或停止监控会取消等待并暂停定时采样。修改间隔、插拔和唤醒通知仍只读取已有数据，避免采样触发通知后循环采样。失败时保留已有读数，并在刷新按钮显示错误。数值相同但时间戳更新仍算新采样；请求失败或超时会明确提示，显示已有读数而不冒充采样成功。

主动采样使用 macOS 私有电池驱动接口，设置的间隔不保证传感器每次都能及时更新。未授权时仍显示已有数据，并在刷新按钮提示采样错误。授权及移除操作的结果显示在「管理员权限授权」区域。

### 开发验证

`bash scripts/test-active-refresh.sh` 使用模拟请求验证定时和手动采样、请求合并、休眠及停止取消、超时、错误处理，以及普通读取不会调用管理员采样。签名应用的 `--configure-admin-service` 会申请管理员授权安装服务并验证一次采样；`--verify-active-refresh` 会检查已安装服务并请求一次真实采样。

`bash scripts/test-power-flow.sh` 验证充放电符号、真实补电、零电流、插拔过渡和功率回退计算；可添加 `--read-system` 只读对照本机。

`bash scripts/test-energy-modes.sh` 验证模式解析、失败和取消、百分比显示、刷新间隔保存与耗能数据解析；添加 `--read-system` 可只读核对本机数据。`bash scripts/test-integration.sh` 验证 XPC 签名准入、非法请求拒绝，以及真实状态栏开关后的弹窗定位。它们不安装服务，也不切换系统电源模式。实际管理员安装/卸载与切换需在 Mac 上手动验证。

## 系统资源

弹窗新增 CPU/GPU 占用率、已用/总内存以及网络上传下载速度。读取无需管理员授权，使用独立的「资源刷新间隔」（默认 2 秒，范围 1–300 秒），与「电池刷新间隔」分开保存和运行；电池服务报错不会阻塞这些指标。点击刷新也会读取这些指标，休眠暂停，唤醒后重新建立计数基准。

CPU、GPU、内存和网速分别提供菜单栏开关，首次默认开启并记住设置。CPU/GPU/MEM 以上下两行显示百分比和名称，网速以上传/下载两行显示，K/s、M/s 为十进制字节每秒。所有指标共用一个紧凑状态栏项目，不增加独立图标之间的系统留白。电量和功率开关保持独立。

CPU 是全部核心在两次内核计数之间的平均忙碌比例。GPU 使用驱动上报的占用率，不支持时显示“—”；多个 GPU 时取占用率最高的一项。内存从驻留、联动、压缩等分页统计估算，扣除可回收/文件缓存，以 GiB 展示。网速按 Lemon 公开实现汇总符合类型条件的网卡 64 位收发计数，分别用上下行增量除以实际时间，计数不增加或回退时该方向显示零。网速单位 B/s、KB/s、MB/s 使用十进制，表示当前流量而不是宽带最大速度。CPU 和网速首次需要两次读数，会在一秒内补读一次。

CPU 温度取已识别的 CPU 传感器平均值，按 M1–M5 机型选择 SMC 键；Intel 在可读时使用 CPU 封装传感器。风扇逐个显示，0 RPM 为有效停转读数，无风扇和无法读取分别处理。SMC 只提供读取，不控制风扇。温度、风扇和磁盘的菜单栏开关默认关闭；菜单栏风扇显示最高转速，弹窗列出各风扇。

启动磁盘读取可写 Data 卷，可用/总量使用十进制 GB。可用空间优先采用系统的重要用途容量（含可清理空间），占用率也按同一个可用量计算，不累加共享 APFS 容器的各个卷。

「菜单栏排列」中的「内存统计口径」可选择“扣除可回收与文件缓存”或“活跃＋不可换出＋压缩”，并显示所选计算公式；默认保持原算法和已保存的选择。两者使用同一份系统快照，并同步作用于弹窗和菜单栏 MEM；这些是占用率，不是内存压力。

`bash scripts/test-hardware-metrics.sh` 验证 SMC 数值解码、机型传感器、内存口径和磁盘容量；添加 `--read-system` 可在普通用户权限下读取实际传感器。

`bash scripts/test-resource-menu.sh` 验证菜单栏全部开关组合、独立间隔保存、实际紧凑宽度和分离调度。

`bash scripts/test-system-metrics.sh` 验证差分计算、计数回绕、接口切换、内存和启停行为；加 `--read-system` 可只读核对本机数据。

## 菜单栏排列与启动项管理

「菜单栏排列」支持拖动或使用箭头调整每一项从左到右的顺序，包括电量和功率。顺序与开关独立保存，隐藏项保留位置。再次点击菜单栏或点击弹窗外部会直接收起，延后的定位任务不会重新打开弹窗。

「启动项管理」按应用和类型分组，一次展开直接显示全部子项及类型标题。应用总开关统一控制可管理子项；全部开启、部分开启、全部关闭分别用绿色、蓝色和灰色标注。搜索只筛选应用，不会缩小总开关的作用范围。列表只在打开窗口、手动刷新和修改后核对时读取，不跟随电量和资源定时刷新。每项提供独立状态、准确文件路径和“在 Finder 中显示原文件”。支持逐项管理传统登录应用、符合条件的用户/共享 LaunchAgent 和 `/Library/LaunchDaemons` 服务。关闭传统登录应用时保留其路径和隐藏设置，以便恢复；开启受支持的 launchd 服务时，允许自启动并立即加载尚未加载的项目，再核对注册结果；关闭会禁止后续自动启动并立即卸载后台服务，再核对是否已从加载列表移除；普通登录应用仅修改登录启动设置。修改系统服务及读取后台项目均复用现有管理员服务，不再逐次弹出密码框。

应用内托管服务或受 macOS 后台权限控制的项目，无法直接修改时会引导到系统设置，不提供假开关。系统自带服务不列入管理；PowerTop 电池服务仍由“管理员权限授权”管理。相同服务标识对应多个文件时只读显示，避免错误地声称可只切换其中一个文件。打开、搜索和刷新列表都不会改动启动设置。现代后台信息通过 `sfltool dumpbtm` 读取，传统登录应用使用兼容 SharedFileList 接口，并在修改后重新核对实际状态。

`bash scripts/test-startup-layout.sh` 使用模拟后端验证子项隔离、解析和来源校验，并检查菜单栏排序、颜色及原生弹窗反复开关；加 `--read-system` 仅额外读取本机启动项，不修改它们。

## 按需读取与缓存

菜单栏不再显示悬停数据提示，保留辅助功能朗读标签。弹窗关闭时只读取菜单栏选中的系统资源，打开时补读全部资源；全部资源关闭时停止资源轮询。温度与风扇分别按需读取。磁盘容量缓存 60 秒（包括暂时不可用的结果）；打开弹窗或手动刷新时立即重新读取；菜单栏只有磁盘时，刷新周期不会短于 60 秒。新启用 CPU/网速时会在一秒内补齐第二次计数采样。

电池主动采样及用户设置的间隔不变。序列号、设备型号、设计循环次数、制造日期使用缓存，电池身份变化或设备不可用时失效。电芯节点与寿命详情只在电池详情窗口打开时读取，关闭或最小化后停止电芯遍历。功率、充放电状态、健康度仍按原周期更新。驱动仍执行原有 ReadAll 请求，此处减少的是应用侧工作，不代表减少了硬件采样范围。

`bash scripts/test-demand-reading.sh` 验证可见项选择、空闲与低频调度、缓存到期、电池详情生命周期和悬停提示移除。

启动服务按 Lemon 的加载状态显示：只要已加载就显示开启，不再要求自启动配置同时允许；允许但未加载时显示关闭并标注“未加载”；未加载且已禁用时显示关闭，不加额外标识。已加载但等待触发的服务仍视为已加载。读取失败显示状态未知并禁用操作，不能误判为关闭。仅限 LoginWindow 等其他会话的服务不能强行加载到当前 Aqua 桌面会话，点击开启时提示原因，不改变其设置。加载状态只随启动项列表读取及操作核对，不跟随电池或资源刷新。

网络汇总对齐 Lemon 公开提交 `7ff8676`：优先累加以太网（含 Wi-Fi）、PPP、Modem、蜂窝接口，不额外按 UP/RUNNING 过滤。仅当这些接口的累计接收字节总和为零时，回退到排除 LOOP、GIF、STF、PKTAP 后的其他接口。按需读取和用户刷新间隔不变；采样时间窗口不同仍可能使两款应用的瞬时数字不同。

电量和瓦数改为与 CPU 一致的双行“数值＋BAT/PWR 标签”，黄色仅作用于这两个电源相关列。充电闪电紧跟电量数值，隐藏电量时跟随瓦数。内存与磁盘容量小字收纳到弹窗百分比的悬停提示中。

多屏菜单栏按数值和实际颜色去重绘制，合并重复外观通知，并预先生成 1x/2x 位图，避免外接显示器复制状态栏时触发循环重绘。
